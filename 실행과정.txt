  [6] 다중 클라이언트 동시 접속
  --------------------------------------------------------
  ( 웹과 CLI가 동시에 서버에 접속 - 서버는 클라이언트 종류를
    구분하지 않고 동일 JSON 프로토콜로 처리 )

  [서버 로그]
  클라이언트 접속: 127.0.0.1            <- 웹서버(조도 폴링)
  수신: {"v":1,"cmd":"LIGHT","args":{},"id":1}
  클라이언트 접속: 100.115.37.33        <- CLI 클라이언트
  수신: {"v":1,"cmd":"LED","args":{"state":"ON","level":"HIGH"},"id":1}

  ( 두 클라이언트의 명령이 충돌 없이 순차 처리됨 )


  [7] Last-Write-Wins (다중 제어 정상 동작)
  --------------------------------------------------------
  ( 웹에서 LED ON )
   웹 -> {"cmd":"LED","args":{"state":"ON","level":"HIGH"}}
      -> {"ok":true,...,"bright":"HIGH"}   (LED 켜짐)

  ( CLI에서 LED OFF )
   CLI -> {"cmd":"LED","args":{"state":"OFF"}}
       -> {"ok":true,...,"state":"OFF"}    (LED 꺼짐)

  => 나중 명령이 반영됨 (정상). dispatch_mutex로 GPIO 동시
     접근은 보호되며, 순차 명령은 마지막 명령이 적용된다.


  [8] 동기화 - 카운트다운 중복 방지 (Semaphore)
  --------------------------------------------------------
  (터미널1) {"v":1,"cmd":"COUNTDOWN","args":{"value":9},"id":1}
   -> {"ok":true,"cmd":"COUNTDOWN","data":{"value":9},"id":1}
      (카운트다운 진행 시작)

  (터미널2, 진행 중 재요청) {"v":1,"cmd":"COUNTDOWN","args":{"value":9},"id":1}
   -> {"ok":false,"cmd":"COUNTDOWN","error":"BUSY",
       "message":"카운트다운 진행 중","id":1}

  => 세마포어(초기값 1)로 동시에 1개의 카운트다운만 실행.


  [9] 동기화 - AUTO 모드 중복 방지 (Mutex)
  --------------------------------------------------------
  (AUTO ON 두 번 연속 요청)
   1차 -> {"ok":true,"cmd":"AUTO","data":{"state":"ON"}}  (스레드 생성)
   2차 -> {"ok":true,"cmd":"AUTO","data":{"state":"ON"}}  (이미 실행 중,
          auto_mutex로 보호되어 스레드 중복 생성 안 함)

  [서버 로그] - AUTO 스레드는 1개만 동작 (1초에 1회 출력)
  [AUTO] light=150
  [AUTO] light=211   <- 센서 가림 -> LED 자동 ON
  [AUTO] light=148   <- 밝아짐   -> LED 자동 OFF


  [10] AUTO 모드 동작 (조도 -> LED 자동 제어)
  --------------------------------------------------------
  선택 > 10
  응답: {"ok":true,"cmd":"AUTO","data":{"state":"ON"},"id":10}
   ( 센서 가림 -> 조도값 상승 -> LED 자동 ON )
   ( 밝아짐    -> 조도값 하락 -> LED 자동 OFF )

  선택 > 11
  응답: {"ok":true,"cmd":"AUTO","data":{"state":"OFF"},"id":11}

  [12] 잘못된 요청 처리 (에러 응답)
  --------------------------------------------------------
  ( 잘못된 JSON )
   -> {"ok":false,"error":"BAD_JSON","id":0}

  ( 정의되지 않은 명령 )
   {"v":1,"cmd":"XXX","args":{},"id":1}
   -> {"ok":false,"cmd":"XXX","error":"UNKNOWN_CMD","id":1}

  ( 잘못된 인자 )
   {"v":1,"cmd":"SEG","args":{"value":99},"id":1}
   -> {"ok":false,"cmd":"SEG","error":"BAD_ARG",
       "message":"value must be 0~9","id":1}
